# Day 64 笔记｜记忆写入策略

## 1. 一句话定位

**记忆写入策略**：在「向量库能存」之前，先决定「这句话该不该成为长期记忆」——用闸门过滤噪声、敏感信息与一次性任务。

## 2. 前端迁移直觉

| 你熟悉的前端 | Agent 写入策略 |
|--------------|----------------|
| 表单校验后再 `POST` | 决策后再 `remember()` |
| 防抖 / 节流少发请求 | 默认 SKIP，少写库 |
| 隐私字段不落日志 | 敏感模式直接 SKIP |
| Confirm Modal | ASK → HITL 后再写 |
| Feature flag 控制埋点 | 策略可配置、可审计 |

结论：长期记忆是**产品状态变更**，不是聊天副产品。写库 ≈ 发一个有副作用的 API。

## 3. 三态决策

```text
用户话语
   │
   ▼
decide_write()
   ├─ WRITE → 交给 VectorMemoryStore（Day 63）
   ├─ SKIP  → 丢弃（寒暄 / 一次性 / 敏感 / 无信号）
   └─ ASK   → 弹出确认（犹豫的偏好等）→ 用户同意后再 WRITE
```

## 4. 推荐决策顺序（今日练习）

```text
1. 非 user 角色          → SKIP
2. 空文本                → SKIP
3. 敏感信息              → SKIP（永不 ASK）
4. 「不要记住」          → SKIP
5. 「请记住 / 以后都」   → WRITE（高置信）
6. 寒暄闲聊              → SKIP
7. 过短噪声              → SKIP
8. 偏好信号 ± 犹豫词     → WRITE 或 ASK
9. 事实信号              → WRITE
10. 其他                 → SKIP（默认不记）
```

顺序很重要：例如「谢谢」若先做「过短」判断，reason 会不准；寒暄要优先于长度检查。

## 5. 什么该记？什么不该？

| 该记（倾向 WRITE） | 不该记（SKIP） | 先问人（ASK） |
|-------------------|----------------|---------------|
| 「请记住我用中文」 | 「你好 / 谢谢」 | 「我可能喜欢浅色」 |
| 「我喜欢深色主题」 | 「帮我改这个按钮」 | 信号冲突、置信低 |
| 「我叫小凯，前端」 | 密码 / API Key | — |
| 稳定工作习惯 | 单次调试上下文 | — |

## 6. 和 Day 63 / Day 59 的衔接

```text
Day 64 策略                  Day 63 存储               Day 59 HITL
decide_write()
  WRITE ──────────────────► upsert / remember_preference
  ASK ────────────────────► confirm hook ──同意──► upsert
  SKIP ─► （结束）
```

今天练习只做策略层；真正持久化沿用昨天的 Store 接口即可。

## 7. 规则 vs LLM 分类器

| | 规则启发式（今天） | LLM 分类 |
|--|-------------------|----------|
| 成本 | 零 token | 每句都花钱 |
| 可测性 | 单测友好、确定性 | 需 golden set |
| 覆盖率 | 模式有限 | 更懂语义 |
| 生产建议 | 先上规则 + 显式指令 | 难例再升 LLM |

前端直觉：先用 if/正则做校验，再考虑上 ML——Agent 记忆同理。

## 8. 常见坑

| 坑 | 正确做法 |
|----|----------|
| 全量写入向量库 | 默认 SKIP，有信号才写 |
| 敏感内容走 ASK | 直接 SKIP，避免泄露到 UI/日志 |
| 只认中文或只认英文 | 正则里双语信号都留一点 |
| 无 reason / 无 confidence | 决策要可审计，方便调参 |
| 把 assistant 回复当用户偏好 | 通常只从 user 侧抽取 |
