# Day 63 笔记｜长期向量记忆

## 1. 一句话定位

**长期向量记忆**：把「用户偏好 / 稳定事实」写成可检索条目，跨会话保存；需要时按语义召回，注入当前请求——而不是每轮都塞进上下文。

## 2. 前端迁移直觉

| 你熟悉的前端 | Agent 长期记忆 |
|--------------|----------------|
| `localStorage` / 用户设置 | 偏好条目持久化 |
| 全局 store 按 `userId` 分区 | `user_id` 隔离检索 |
| 搜索联想 / fuzzy find | embedding + 余弦相似度 |
| 按需懒加载模块 | 按需召回，不预塞全量 |
| Feature flag 面板 | 记忆注入块可开关、可审计 |

结论：长期记忆是**产品状态**，不是「模型自己会记住」。你负责写什么、何时取、取几条。

## 3. 三种记忆对照（Week 13）

```text
短记忆（D61）          摘要记忆（D62）         长期向量记忆（今天）
├─ 当前会话窗口         ├─ 当前会话内压缩        ├─ 跨会话
├─ 裁剪 / pinned        ├─ 滚动 summary         ├─ embed + 检索
├─ 几乎每轮都带上       ├─ 仍挂在请求前部        ├─ 按需注入
└─ 会话结束通常丢       └─ 会话结束通常丢        └─ 可持久化（DB/文件）
```

今天练习用**进程内 dict** 模拟存储；生产换成 SQLite / pgvector / 云向量库即可，接口形状不变。

## 4. 推荐注入形状

```text
[system] 你是……
[system] [长期记忆]
         - (preference, score=0.82) 喜欢深色主题……
         - (preference, score=0.71) 代码示例优先 TypeScript
[user] 帮我改一下按钮样式
```

练习约定：注入块以 `[长期记忆]` 开头，方便测试与前端识别。

## 5. 为什么要「假 Embedding」？

| 场景 | 用什么 |
|------|--------|
| 练习 / CI | `mock_embed`（字符 n-gram 哈希）→ 稳定、免费、可测 |
| 本地联调 | OpenAI / 国产 Embedding API（Day 33） |
| 生产 | 同上 + 维度一致的向量库 |

接口保持一致：

```python
EmbedFn = Callable[[str], list[float]]
```

换真模型时，只换 `embed_fn`，`VectorMemoryStore` 不用重写。

## 6. 用户隔离为什么是硬规则？

多租户 Agent 最常见事故：A 用户的偏好被召回到 B 的上下文。

```text
search(query, user_id=...)
  → 先 filter user_id
  → 再算相似度
  → 再 top_k / min_score
```

**先隔离，再检索**——顺序不能反。

## 7. 和 RAG（Phase 2）的差别

| | RAG 文档库 | 长期记忆 |
|--|-----------|----------|
| 内容 | 知识文档 chunk | 用户偏好 / 事实 / 笔记 |
| 生命周期 | 随知识库更新 | 随用户画像演化 |
| 注入时机 | 每次问答检索 | 会话开始或相关意图时 |
| 权限 | 常共享语料 | **必须按用户隔离** |

技术上都是「embed → 存 → 搜」，产品语义不同。

## 8. 常见坑

| 坑 | 正确做法 |
|----|----------|
| 把全部偏好塞进 system | 只召回 top_k，设 min_score |
| 用 Python `hash()` 做 embedding | 不稳定；用固定哈希或真 API |
| 不隔离 user_id | 隐私事故；测试必须覆盖跨用户 |
| 把临时闲聊都当长期记忆 | 明天 D64：写入策略 / 启发式 |
| 召回块没有标记 | 用 `[长期记忆]` 等前缀，便于审计与前端展示 |

## 9. 今日一句话

> 跨会话的偏好别指望模型「自己记得」：写成向量条目，按用户隔离检索，需要时再注入。
