# Day 21 笔记｜Prompt 结构拆解

## 1. 今天学什么？

很多人写 Prompt 像写微博：想到哪写到哪。结果是：

- 改一处牵全身，无法 diff
- 同任务多场景复制粘贴，规则漂移
- 出了幻觉 / 格式错，说不清缺的是「角色」还是「约束」

今天练的是：**把 Prompt 当成组件，而不是散文**。

| 组件 | 解决的问题 | 前端类比 |
|------|------------|----------|
| 角色 (role) | 立场、语气、专业边界 | 组件的 `props.variant` / 角色权限 |
| 任务 (task) | 本轮交付物是什么 | 函数签名的「做什么」 |
| 约束 (constraints) | 不能做什么、必须遵守什么 | 校验规则 / guardrails |
| 输出格式 (output_format) | 结果长什么样 | TypeScript 返回类型 / Schema |
| 上下文 (context，可选) | 本轮额外资料 | 注入的 props / store 切片 |

> Phase 2 的主线：先能**稳定地描述任务**，再谈结构化输出与 RAG。

## 2. 为什么要拆？

对比两种写法：

**散文版（难维护）**

```text
你是个厉害的助手，请帮我总结下面文字，别太长，用中文，要点清晰，不要瞎编……
（后面再贴一大段原文）
```

**组件版（可测、可复用）**

```text
【角色】
你是技术文档编辑，擅长把口语整理成条理清晰的要点。

【任务】
将用户提供的段落压缩为 3 条要点。

【约束】
- 只使用原文信息，不得臆造
- 使用简体中文
- 每条不超过 40 字

【输出格式】
纯文本，每行一条，形如：1. ...
```

组件版的好处：

1. **可单测**：渲染结果章节齐全、顺序固定
2. **可替换**：同一角色换任务，或同一任务换约束
3. **可协作**：前后端 / Prompt 评审时按字段讨论，而不是对着墙字

## 3. System vs User：别把一切塞进一条

| 消息角色 | 适合放什么 | 不适合 |
|----------|------------|--------|
| `system` | 角色、稳定规则、输出格式、长期约束 | 每次都变的用户原文 |
| `user` | 本轮输入、待处理文本、问题 | 「你永远是某某」这类稳定设定 |

记忆口诀：

> **system = 说明书；user = 本次工单。**

今天的 `build_chat_messages` 就是按这个约定组装。

## 4. 约束怎么写才有效？

差约束：

- 「尽量好一点」「不要乱说」（主观、不可检查）

好约束：

- 「不得使用原文未出现的专有名词」
- 「若信息不足，回复：信息不足」
- 「禁止输出 Markdown 代码块」

写约束时问自己：**我能不能写一条自动化断言检查模型有没有违反？**  
（Day 26 起会用 schema 把「格式」真正校验起来。）

## 5. 模板库最小 API（今日练习）

```python
spec = PromptSpec(
    role="你是简洁的技术编辑",
    task="把用户文本压缩为 3 条要点",
    constraints=["只用原文信息", "简体中文"],
    output_format="每行一条：1. ...",
    context=None,
)
system = render_system_prompt(spec)
messages = build_chat_messages(spec, user_input="……")
```

实现时注意：

- 空 `role` / `task` / `output_format` → `ValueError`（fail fast）
- `constraints` 允许空列表（表示「无额外约束」），但渲染时整节省略
- 章节顺序固定：角色 → 任务 → 约束 → 输出格式 → 上下文
- 空白要规范化，避免复制粘贴带进奇怪空行

## 6. 和前端经验的映射

你已经习惯：

```ts
<Button variant="primary" disabled={loading} />
```

Prompt 也可以是「声明式 UI」：

```text
<Prompt role=... task=... constraints=[...] format=... />
```

Agent 工程后期会把这类模板版本化、评测、A/B——**今天先把拼装做对**。

## 7. 今日一句话

> Prompt 不是灵感，是接口：角色定立场，任务定交付，约束定边界，格式定形状。
