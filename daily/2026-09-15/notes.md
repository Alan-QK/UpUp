## 2. 什么是 Golden Set？

一小撮**人工标定**的「问题 → 期望行为」样例，例如：

| 字段 | 含义 |
|------|------|
| `question` | 用户怎么问 |
| `expect_refuse` | 该不该拒答 |
| `expected_sources` | 若该答，top-k 里应出现哪些文档 |

它不是「训练集」，是**验收夹具**。前端同学可以类比：e2e fixture / visual snapshot——数量不必多，但要覆盖主路径与边界。

今天练习用 **8 条**就够：5 条应答 + 3 条应拒。

## 3. 两类检查，不要混

| 检查 | 问的是什么 | 典型失败 |
|------|------------|----------|
| **Hit（命中）** | top-k 里有没有期望文档 | 切分太碎、embedding 跑题、库脏 |
| **Gate（门控）** | 该拒的拒了、该答的放行了 | 阈值过高/过低 |

只看「模型最终说了啥」会把检索问题与生成问题缠在一起。先评检索与门控，再评生成（后期可加 LLM-as-judge）。

## 4. 三个比率

```text
hit_rate       = 应答案例中 hit=True 的比例
gate_accuracy  = 全部样例中 gate_ok 的比例
pass_rate      = 应答案例需 gate_ok∧hit；拒答案例需 gate_ok
```

前端类比：

- `hit_rate` ≈ 搜索结果相关性抽检通过率  
- `gate_accuracy` ≈ 空态 / 拦截逻辑是否按预期触发  
- `pass_rate` ≈ 这一轮回归的总绿灯率

## 5. 调参怎么用报告？

1. 先固定 golden set，跑出基线 `pass_rate`
2. 只改一个旋钮（如 `min_top_score` 0.55 → 0.70）
3. 对比表格：哪些 `id` 从 true → false
4. 决定是改阈值、补文档，还是改切分

**一次只动一个变量**——否则你不知道谁害的。

## 6. 人工抽检仍有价值

自动指标抓「结构对不对」；人工抽检抓「语义舒不舒服」：

- 命中文档对，但 chunk 截断把关键句切没了  
- 拒答文案生硬，用户不知道下一步做什么  

两者互补。今天先把自动化骨架搭好。

## 7. 常见误解

| 误解 | 纠正 |
|------|------|
| 样例越多越好 | 先保证可维护；脏样例会误导调参 |
| 有 chat 人工试一下就行 | 人会遗忘边界；自动化才防回退 |
| 指标 100% 才算完成 | 先稳定可复现；再逐步加难例 |
