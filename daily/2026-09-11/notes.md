# Day 37 笔记｜引用溯源

## 1. 今天在路线图里的位置

```text
D36：能基于资料生成答案
        ↓
D37：答案必须能指回具体 chunk（今天）
        ↓
D38 拒答 · D39 评测 · D40 mini-rag 里程碑
```

没有引用的 RAG，用户无法验证——前端也画不出「来源」侧栏。

## 2. 为什么要溯源？

| 角色 | 没有引用时 | 有引用时 |
|------|------------|----------|
| 用户 | 只能盲信模型 | 可点开原文核对 |
| 前端 | 只能渲染纯文本 | 答案 + Sources 面板 |
| 工程 | 难排查幻觉 | 可对照 chunk 做评测 |

一句话：**引用把「生成」重新锚回「检索」。**

## 3. 前端类比

| 前端 | 今日概念 |
|------|----------|
| 搜索结果列表 | `RetrievedChunk` / contexts |
| 富文本里的脚注 `[1]` | `parse_cited_ranks` |
| 侧栏 Sources 列表 | `Citation` + `format_sources_block` |
| 页面 ViewModel | `CitedAnswer` |

你熟悉「列表数据 → 选中项 → 详情面板」。这里是「检索命中 → 答案标记 → 来源面板」。

## 4. 两种展示策略

| mode | 行为 | 适合 |
|------|------|------|
| `mentioned` | 只展示答案里写到的 `[N]` | 严格溯源、减少噪声 |
| `all` | 展示本次全部 top-k 命中 | 调试检索、透明「模型看过什么」 |

练习默认 `mentioned`：答案没写标记 → `(无引用)`，逼你认真对待标记协议。

## 5. 标记协议（最小可用）

约定模型（或假生成器）在用到某条资料时写上 `[rank]`，与 Prompt 里的编号一致：

```text
答案：……降低幻觉[1]，前端可做引用面板[2]。

来源：
[1] source=rag_basics.md id=rag_basics.md#0 score=0.91xx
    RAG（Retrieval-Augmented Generation）…
```

生产里还可以让模型输出 JSON `{"answer","citations":[1,2]}`（Day 26 结构化输出），今天先用文本标记——和多数聊天 UI 一致。

## 6. 常见误解

| 误解 | 纠正 |
|------|------|
| 把全部 contexts 塞进侧栏就叫溯源 | 用户关心的是「这句话依据哪段」 |
| 分数最高的一定被引用 | 模型可能只用了 `[2]`；以标记为准 |
| 引用 = 答案正确 | 引用只证明「看过这段」；对错还要评测（D39） |

## 7. 今日一句话

> 可交付的 RAG 输出 = 答案文本 + 可点击的来源 chunk。
