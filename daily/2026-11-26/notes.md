# Day 71 笔记｜何时用多智能体

## 1. 一句话定位

**多智能体**：把任务拆给多个「专职角色」协作；只有当分工与交接的收益 > 协调成本时才值得做。

## 2. 先打破三个幻觉

| 幻觉 | 现实 |
|------|------|
| Agent 越多越聪明 | 更多是**角色专业化**与**视角隔离**，不是智商叠加 |
| 多智能体 = 更强推理 | 多数收益来自流程（流水线 / 审校），单 Agent + Plan 也能做 |
| 先搭框架再谈要不要 | 先清单决策；很多任务该停在 Day 70 的单 Agent 闭环 |

## 3. 适用信号（Pro）

| 信号 | 含义 | 例子 |
|------|------|------|
| 专职角色 | 能叫出不同岗位 | Researcher / Writer / Reviewer |
| 流水线交接 | A 的产出是 B 的输入 | 调研笔记 → 成稿 |
| 可并行 | 独立工作流可同时推进 | 两路资料搜集 |
| 对立审校 | 需要「唱反调」的独立视角 | 安全审计挑刺 |
| 异构工具集 | 角色工具几乎不重叠 | 检索工具 vs 发布工具 |

## 4. 不适用信号（Con）

| 信号 | 含义 | 例子 |
|------|------|------|
| 单技能循环 | 查一下就能答 | 天气 / FAQ |
| 延迟紧 | 多一轮协调就超时 | 即时客服气泡 |
| 成本敏感 | token 预算紧 | 高频内部工具 |
| 角色模糊 | 拆不开职责 | 「再加个聪明助手」 |
| 重共享可变状态 | 大家抢同一份脏状态 | 无协议的共同编辑 |

## 5. 今日决策规则（教学版）

```text
画像布尔信号
    │
    ├─① 角色模糊且叫不出专职 → keep_single（否决）
    ├─② 纯单技能循环且无强拆分信号 → keep_single（否决）
    ├─③ 正信号 ≥ 2 且 score ≥ 3 → use_multi
    ├─④ score ≤ 0 或负信号占优 → keep_single
    └─⑤ 其余 → defer（先跑通单 Agent）
```

`score = Σ(pro 权重) − Σ(con 权重)`。权重是教学启发式，生产里可换成你们的成本/延迟模型。

## 6. 前端迁移直觉

| 你熟悉的前端 | 今日对应 |
|--------------|----------|
| 多人协作看板（列 = 角色） | 多智能体拓扑 |
| 一个超级组件包办一切 | 单 Agent + 多步 |
| 微前端拆分的「边界清晰」原则 | 角色切不清就别拆 |
| 性能预算 / 包体积预算 | token / 延迟预算 |
| Feature flag 灰度 | `defer`：先单后多 |

结论：拆多智能体 ≈ **拆服务 / 拆微前端**——边界清晰才拆，不是为了简历关键词。

## 7. 与 Day 70 的关系

```text
Day 70：一个 Agent 内部 Plan → Execute → Reflect
Day 71：决定要不要变成多个 Agent 协作
Day 72：若决定拆，先落地最简单的流水线双 Agent
```

多数业务停在 Day 70 就够用。Week 15 教你**有纪律地**升级。

## 8. 常见坑

| 坑 | 修好 |
|----|------|
| 还没单 Agent 闭环就上 Multi | 先完成 Day 70 类管线 |
| 用「感觉复杂」当拆分理由 | 改成可勾选信号清单 |
| 角色名很炫但职责重叠 | blurry_roles → 否决 |
| 忽略协调税 | 把 tight_latency / cost_sensitive 勾上 |
