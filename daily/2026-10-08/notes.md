# Day 55 笔记｜周挑战：手写 vs 框架对比

## 1. 为什么今天写「对比报告」？

Week 11 不是让你「学会某个库」，而是走完一条认知闭环：

| Day | 你得到了什么 |
|-----|--------------|
| 51 | 选型尺子（目标 / 熟练度 / 锁定风险） |
| 52 | 手写 Loop ↔ 框架抽象的映射表 |
| 53 | 在框架风格 API 上扩业务工具 |
| 54 | 给产品 UI 的流式事件协议 |
| **55** | **把体验写成可决策文档** |

没有今天这步，本周知识会停在「感觉框架挺方便」——面试与团队讨论都讲不透。

## 2. 前端迁移直觉

| 你熟悉的前端 | 今天的对比 |
|--------------|------------|
| 手写 `useReducer` vs 上 Zustand | 手写 Loop vs Runner/Registry |
| 自己发 action vs 用中间件封装 | 手写 `print` vs `on_event` |
| 「先懂状态流，再选状态库」 | 「先懂 Agent Loop，再选框架」 |
| ADR / 技术选型一页纸 | 今日 `render_comparison_report` |

结论：对比报告 = Agent 版 **ADR（Architecture Decision Record）** 草稿。

## 3. 六个对照维度（练习会编码）

分数约定：**1–5，越高越好**（含「锁定安全性」——越不容易被厂商/API 绑死越高）。

| 维度 ID | 含义 | 手写通常 | 框架通常 |
|---------|------|----------|----------|
| `control` | 对 Loop / 终止 / 工具白名单的掌控 | 高 | 中 |
| `clarity` | 概念是否一眼可见（messages / tool_calls） | 高 | 中低（抽象厚） |
| `velocity` | 同等能力落地速度 | 中低 | 高 |
| `extensibility` | 加工具、接事件、接业务的顺滑度 | 中 | 高（约定成熟时） |
| `debug` | 排错是否好跟（堆栈、状态、日志） | 高（全在你手里） | 中（要懂框架路径） |
| `lockin_safety` | 降低厂商/库锁定风险 | 高 | 中低 |

> 分数是教学默认值，不是永恒真理。换团队约束时，你应重打分。

## 4. 目标决定赢家（别和稀泥）

```text
learn_loop / interview  → 主选 handwritten
ship_product / onboard  → 主选 framework
```

理由一句话：

- **学懂 / 面试**：你要能指着代码讲 Loop；框架会藏细节
- **上线 / 带新人**：你要约定、脚手架、社区答案；手写样板会拖累协作

迷你框架（Day52）的定位：**教学对照层**，不是第三个「生产候选」。报告里把它当作「理解框架概念的桥」，最终生产决策仍在 handwritten ↔ 真实框架之间。

## 5. 一份合格报告至少有什么？

1. **本周回顾**：51–54 各一句，证明你不是空对比  
2. **对照维度**：表格或列表，写出两侧分数与短注  
3. **手写优势** / **框架优势**：各列赢面维度，禁止两边都写「都很好」  
4. **决策建议**：绑定具体 goal，给出主选 + 一句为什么  
5. **下周预告**：安全与里程碑（Prompt Injection 起）

篇幅：一页到两页 Markdown，同事 5 分钟能读完拍板。

## 6. 常见坑

| 坑 | 症状 | 纠正 |
|----|------|------|
| 用星标数对比 | 「LangChain stars 多所以赢」 | 回到 6 维度 + 你的 goal |
| 没同能力对照 | 手写只有 echo，框架却接了 RAG | 固定能力集再比 |
| 永远 handwritten | 怕抽象就拒绝一切库 | 交付场景允许框架放大产能 |
| 永远框架 | 不会排 Loop 错却上生产 | 先保住 Day46–50 的手写肌肉 |

## 7. 今日一句话

> 框架是放大器：你懂 Loop，它放大产能；你不懂 Loop，它放大困惑——对比报告就是把这句话写成可执行决策。
