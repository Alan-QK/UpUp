# 前端 → AI Agent 开发工程师 · 半年转型总纲

> 版本：v1.0 · 起始日期：2026-07-14  
> 对象：高级前端工程师，Python 有一点基础  
> 目标：具备可上岗的 AI Agent 开发能力（设计、实现、评测、部署、与前端协同）

---

## 一、转型定位

### 1.1 你要成为什么样的人

**AI Agent 开发工程师** 不是只会调 GPT 聊天，而是能把 LLM 做成**可执行任务的系统**：

| 能力维度 | 具体表现 |
|----------|----------|
| 模型使用 | 熟练使用主流 LLM API（OpenAI / 兼容接口 / 国产大模型） |
| Agent 编排 | 工具调用、规划、多步推理、失败重试与人机协作 |
| 知识增强 | RAG、文档切分、向量检索、引用与幻觉控制 |
| 工程落地 | API 服务、异步、状态/记忆、日志、评测、成本控制 |
| 产品结合 | 把 Agent 接到前端（流式输出、工具状态、会话 UI） |

### 1.2 发挥前端优势（不要丢掉）

前端背景是优势，不是包袱：

- **交互与状态机思维** → Agent 会话状态、流式 UI、工具执行反馈
- **TypeScript/工程规范** → Agent 输出结构化（JSON Schema）、类型安全工具层
- **组件化** → 把 Prompt、Tool、Memory、Evaluator 拆成可复用模块
- **产品感** → 先做能用的 Agent，再做炫技的 Multi-Agent

### 1.3 半年后的验收标准（作品集）

完成以下至少 **3 个可演示项目**：

1. **工具调用 Agent**：能查天气/搜文档/读写文件等，带错误处理
2. **RAG 问答系统**：本地或云端知识库 + 引用溯源
3. **全栈 Agent 应用**：Python Agent 后端 + 你熟悉的前端（流式对话 + 工具面板）

可选加分项：多智能体协作 Demo、评测报告、可观测 Dashboard。

## 三、阶段目标一览

### Phase 1｜Python 强化 + LLM 基础（Week 1–4）

**目标**：能用 Python 写清晰脚本/小模块，并完成第一次 LLM API 调用。

- Python 语法巩固：类型注解、dataclass、异常、模块、虚拟环境
- 异步基础：`asyncio`、`httpx`/`aiohttp`
- HTTP/JSON、环境变量与密钥管理
- OpenAI 兼容 API：聊天、流式、token 与成本意识
- 里程碑：`cli-chatbot`（命令行流式聊天机器人）

### Phase 2｜Prompt、结构化输出与 RAG 入门（Week 5–8）

**目标**：稳定地让模型按格式输出，并搭一个最小 RAG。

- Prompt 设计模式、Few-shot、角色与约束
- JSON Schema / Structured Outputs / 校验与重试
- 文档切分、Embedding、向量库（如 Chroma / FAISS）
- 检索质量、引用与简单评测
- 里程碑：`mini-rag`（上传文档 → 问答带引用）

### Phase 3｜Agent 核心能力（Week 9–12）

**目标**：手写一个 ReAct/Tool-Calling Agent，再对比框架实现。

- Tool Calling 协议与函数设计
- Agent Loop：观察 → 思考 → 行动 → 结束
- 框架入门：LangChain / LlamaIndex / 官方 Agents SDK（择 1–2 深入）
- 安全：权限边界、Prompt Injection 基础防护
- 里程碑：`tool-agent`（多工具 Agent + 单元测试）

### Phase 4｜记忆、规划与多智能体（Week 13–16）

**目标**：理解长期记忆与协作拓扑，能搭简单 Multi-Agent。

- 短期/长期记忆、摘要记忆、向量记忆
- Planning：计划-执行、反思、任务分解
- Multi-Agent：主管-工人、辩论、流水线
- 人机协作：HITL、确认节点
- 里程碑：`research-crew`（调研 → 写作 → 审校多智能体）

### Phase 5｜工程化与生产意识（Week 17–20）

**目标**：把 Agent 当真实服务来做。

- FastAPI 服务化、SSE/WebSocket 流式
- 会话存储、限流、超时、重试与幂等
- 评测：golden set、轨迹评测、回归
- 可观测：日志、Tracing（如 OpenTelemetry / LangSmith 概念）
- 成本与延迟优化
- 里程碑：`agent-api`（可部署的 Agent API + 基础评测脚本）

### Phase 6｜综合项目与作品集（Week 21–24）

**目标**：交付可演示全栈作品，整理面试叙事。

- 前端对接：流式对话、工具执行状态、取消请求
- 端到端项目打磨与 README/演示视频脚本
- 常见面试题与系统设计题复盘
- 缓冲周：查漏补缺、开源贡献或博客

## 四、技术栈建议（刻意克制）

### 必学（主线）

| 类别 | 选型 |
|------|------|
| 语言 | Python 3.11+（类型注解优先） |
| 包管理 | `uv` 或 `poetry`（二选一坚持） |
| HTTP | `httpx` |
| API 服务 | FastAPI + Uvicorn |
| LLM | OpenAI 兼容接口（便于切换模型） |
| 向量 | 先 Chroma，再了解 pgvector |
| 测试 | pytest |
| 前端联动 | 你现有栈（Vue/React）+ fetch/SSE |

### 选学（按兴趣/工作需要）

- LangGraph / CrewAI / AutoGen（多智能体）
- LlamaIndex（偏 RAG）
- Redis（会话/队列）
- Docker 基础部署
- 国产模型 API（通义、DeepSeek、智谱等）

### 刻意后置（前期不要陷入）

- 从零训练/微调大模型
- 复杂 MLOps / 分布式训练
- 过度堆框架，还没手写过 Agent Loop

**原则：先手写最小实现，再引入框架理解其抽象。**

## 七、学习原则（请置顶）

1. **输出驱动**：每天至少有一段可运行代码  
2. **前端迁移**：每学会一个后端概念，想一次「前端怎么展示/交互」  
3. **少而深**：同一周不并行学 3 个框架  
4. **记录失败**：把坏 Prompt、坏检索、死循环 Agent 记进笔记  
5. **安全默认**：密钥进 `.env`，永不提交；工具默认最小权限  
6. **可复盘**：每周五写 10 行「本周学会了什么 / 卡在哪」

## 九、风险与应对

| 风险 | 应对 |
|------|------|
| Python 基础不牢，后期 Agent 代码读不动 | Phase 1 允许延长 1 周，宁可慢 |
| 沉迷调 Prompt，不做工程 | 每周至少一次「可测试」交付 |
| API 费用焦虑 | 优先用便宜/本地兼容模型；练习用 mock |
| 框架版本混乱 | 以官方文档为准，锁定依赖版本 |
| 三分钟热度 | 工作日自动化推送 + 周五小挑战制造闭环 |
